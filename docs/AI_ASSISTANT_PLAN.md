# خطة المساعد الذكي (AI Assistant) — أول موديول في Sitekit

> التاريخ: 2026-11-24
> **الهدف:** مساعد ذكي على المتجر، بيفتح لما العميل يضغط على الماسكوت. شغله:
> - يدوّر في سيارات المعرض الحقيقية، ويقارن بينها، ويحسب الأقساط من بنوك الحاسبة.
> - يرد على أسئلة المعرض (مواعيد العمل، الفروع، المستندات، شروط التمويل).
> - يفهم احتياج العميل من الكلام، ويرشّح له السيارة المناسبة.
> - يحوّله لطلب (Lead/Booking) في الـ CRM.
> - كل حاجة مسموح يتكلم فيها أو ممنوع، بتتحكم فيها من **الإعدادات**.
> - **مزوّد الذكاء قابل للتبديل:** Gemini أولاً، وClaude بعده، وأي مزوّد تاني قدام.

---

## 0. القرارات الأساسية (مقترحة)

| القرار | الاختيار | السبب |
|---|---|---|
| مكانه | **أول موديول حقيقي:** `app/Modules/AiAssistant` | يتفعّل ويتعطّل لكل معرض، ويتحدّث مع النواة، ويبقى نموذج لباقي الموديولات |
| مين بيشغّل الـ loop | **Laravel نفسه** (طلب ← المزوّد ← أدوات ← رد) | لازم يبقى **محايد للمزوّد** (Gemini/Claude/...)، والأدوات بتقرا من الداتابيز مباشرة، وده بيدينا تحكم كامل في القواعد والتكلفة |
| مصدر الحقائق | **الأدوات (Tools) بس** | السعر والقسط والمواصفات والتوفر ممنوع تيجي من "ذاكرة" النموذج. لازم تيجي من نتيجة أداة، ودي أهم حماية من الإجابات الغلط |
| شكل الرد | **Streaming (SSE)** + كروت منظّمة (سيارة، مقارنة، قسط) | العميل يشوف الرد وهو بيتكتب، والكروت بتتعرض بتصميم الفرونت نفسه |
| المفاتيح | في الباك إند بس، ومشفّرة (`Crypt`) | ولا مفتاح بيوصل للمتصفح أبداً |

## 1. تجربة العميل

### 1.1 الماسكوت يفتح الشات
الكومبوننت الحالي `Assistant()` في `resources/noauf/src/pages/Home.tsx` (فقاعة "تبيها كاش ولا قسط؟"):
- **الضغط على الماسكوت أو الفقاعة** بيفتح **`AssistantPanel`** بدل ما يروح لـ `/request-car`.
- **الفقاعة بتظهر** في كل الصفحات (تتنقل من `Home` لـ `Layout`)، والنص جاي من الإعدادات (`greeting_bubble`).
- **على الموبايل:** شيت من تحت بعرض الشاشة. **على الديسكتوب:** لوحة جانبية (400px) جنب الماسكوت.
- **الفقاعة مش بتظهر** لو الموديول متعطّل، أو `enabled_on_storefront = false`.

### 1.2 أشكال الرسائل
| النوع | بيتعرض إزاي |
|---|---|
| نص | فقاعة (Markdown بسيط: عناوين، قوائم، عريض) |
| `cars` | carousel كروت سيارات بتصميم `CarCard` الموجود، وفيه زر "التفاصيل" وزر "أضف للمقارنة" |
| `comparison` | جدول مقارنة (السعر، القسط، المحرك، الحصان، الوقود، المقاعد، الضمان) |
| `installment` | كارت قسط: الدفعة الأولى، المدة، القسط الشهري، البنك، إجمالي السعر، مع ملاحظة إن ده "تقديري" |
| `showroom_info` | كارت فيه المواعيد والفروع (مع رابط خرائط) والتليفون والواتساب |
| `quick_replies` | أزرار اقتراحات ("ميزانيتي شهرية"، "عائلية 7 ركاب"، "قارن بين دول") |
| `lead_form` | فورم صغير جوّه الشات (الاسم، الجوال، الموافقة)، وبعده تأكيد "تم إرسال طلبك" |
| `handoff` | زر "كلّم موظف على واتساب"، والرسالة مكتوب فيها ملخص المحادثة |

### 1.3 السيناريوهات الأساسية
1. **"عايز سيارة"** (مقابلة ذكية): المساعد بيسأل بالتدريج، سؤال أو اتنين في المرة:
   - كاش ولا قسط؟ والميزانية (إجمالي أو قسط شهري)؟
   - الاستخدام (مدينة، سفر، عائلة)؟ وعدد الركاب؟
   - نوع الوقود؟ وماركة مفضّلة؟

   وبعدها `search_cars`، فيطلّع 3 ترشيحات وسبب كل ترشيح.
2. **"قارن بين X وY":** `compare_cars`، فيطلّع جدول، وبعده خلاصة "الأنسب لك لو...".
3. **"قسطها كام؟":** `calculate_installment` بالبنك والمدة والدفعة. ولو العميل قال راتبه، بيتحسب كمان هل القسط في حدود نسبة الاستقطاع.
4. **"شغالين امتى؟ فين الفرع؟ إيه المطلوب للتمويل؟":** `get_showroom_info`.
5. **"عايز أحجز":** `create_lead` بعد موافقة صريحة، وبيروح للـ CRM بمصدر **"المساعد الذكي"**، ومعاه ملخص المحادثة واحتياج العميل.
6. **خارج النطاق:** رد مهذب من الإعدادات، والمساعد بيرجّع الكلام للسيارات.

### 1.4 السياق اللي المساعد بياخده تلقائياً (Context)
- **الصفحة الحالية:** لو العميل في صفحة سيارة، المساعد يعرفها ("السيارة دي...").
- **قايمة المقارنة** (`CompareContext`) واللغة (`ar`/`en`).
- **ملف احتياج العميل:** بيتكوّن من المحادثة نفسها (الميزانية، النوع، الاستخدام، الركاب، الوقود، الماركة، الراتب لو قاله)، وبيتحفظ في `ai_conversations.profile`. وبيتبعت للنموذج في كل رسالة بشكل مختصر، بدل التاريخ كله.
- **المحادثة بتكمل لو رجع:** `session_id` في `localStorage`، والمحادثة بتنتهي بعد مدة من الإعدادات.

## 2. المعمارية

```
 noauf (أو أي فرونت)                       Laravel — Modules/AiAssistant
 ─────────────────────                     ─────────────────────────────────────────────
 Mascot → AssistantPanel                   POST /api/v1/store/assistant/chat   (SSE stream)
   useAssistant() (sitekit-sdk)  ───────►    ├─ Guard: rate limit · session · حجم الرسالة · ساعات التشغيل
   ◄── text deltas + cards (SSE)             ├─ ConversationStore (ai_conversations / ai_messages)
                                             ├─ PromptBuilder: system prompt من الإعدادات + ملف العميل + سياق الصفحة
                                             ├─ AssistantRunner (loop ≤ N tool rounds)
                                             │     ↕
                                             │   LlmProvider (interface)
                                             │     ├─ GeminiProvider   (المرحلة 1)
                                             │     ├─ ClaudeProvider   (المرحلة 3)
                                             │     └─ OpenAiProvider   (اختياري)
                                             │     ↕ tool calls
                                             ├─ ToolRegistry → CarApiService / CompareApiService /
                                             │                 CalculatorService / Settings / Leads
                                             └─ OutputGuard: الأسعار/الروابط/الـ slugs لازم تطابق نتائج الأدوات
```

### 2.1 واجهة المزوّد (Provider-neutral)
```php
interface LlmProvider
{
    /** @param list<ChatMessage> $messages  @param list<ToolDefinition> $tools */
    public function stream(string $system, array $messages, array $tools, ProviderOptions $options): iterable; // yields TextDelta | ToolCall | Usage | Done | Refusal
    public function testConnection(): ConnectionResult;
    public function models(): array; // للقائمة في الإعدادات
}
```
- **`ToolDefinition`:** اسم + وصف + JSON Schema واحد، وكل driver بيحوّله للصيغة بتاعته (Gemini `functionDeclarations`، Claude `tools` + `strict: true`).
- **`AssistantRunner`:** مش بيعرف المزوّد. بيستقبل `ToolCall`، وينفّذ الأداة، ويرجّع النتيجة، ويكمل لحد `Done` أو لحد الحد الأقصى لعدد الجولات.
- **تغيير المزوّد من الإعدادات بس**، من غير أي تعديل في الكود ولا في الفرونت.

### 2.2 Gemini (المرحلة 1)
- **الاتصال:** REST `generateContent` و`streamGenerateContent` مع **function calling**، عن طريق Laravel HTTP client. مفيش SDK رسمي لـ PHP، وده بيوفّر dependency.
- **الإعدادات:** API Key وModel. القايمة بتيجي من `models.list` في نفس الـ API عشان دايماً تبقى الأحدث، والافتراضي آخر موديل Flash متاح وقت التنفيذ.

### 2.3 Claude (المرحلة 3)
- **الاتصال:** **Anthropic PHP SDK الرسمي** (`anthropic-ai/sdk`)، Messages API + tool use + streaming. **محتاج موافقتك على الـ dependency.**
- **الموديل الافتراضي:** `claude-opus-5-5`. والإعدادات فيها قايمة تختار منها: `claude-sonnet-5-5` و`claude-haiku-5-5` (أرخص وأسرع للشات). **الاختيار ليك.**
- **ملاحظات تقنية للتنفيذ:**
  - الـ thinking تلقائي (adaptive)، والعمق بيتحكم فيه بـ `output_config.effort`. أقترح `low` أو `medium` للشات، وده من الإعدادات.
  - مفيش `tool_choice` إجباري. بيتعمل `auto` مع `strict: true` على الأدوات.
  - **الـ prompt caching** على الـ system prompt الثابت والأدوات.
  - التعامل مع `stop_reason: refusal`، وتفعيل **server-side fallbacks** افتراضياً (`fallbacks: "default"`).
- **ليه مش Claude Managed Agents؟** المساعد لازم يشتغل بنفس الأدوات والقواعد مع أي مزوّد (Gemini وغيره)، والأدوات بتقرا من داتابيز المعرض مباشرة. عشان كده الـ loop عندنا في Laravel.

### 2.4 الأدوات (Tools) — مصدر الحقيقة الوحيد
| الأداة | المدخلات | بتعتمد على | بترجّع |
|---|---|---|---|
| `search_cars` | `budget_cash_max`, `budget_monthly_max`, `brands[]`, `type`, `fuel`, `min_seats`, `year_min`, `sort`, `limit≤6` | `CarApiService::list` (+ فلتر القسط) | قايمة مختصرة: slug، الاسم، السعر، القسط من، الصورة، أهم 3 مواصفات |
| `get_car` | `slug` | `CarApiService::findBySlug` | التفاصيل والعروض النشطة والتوفر |
| `compare_cars` | `slugs[2..3]` | `CompareApiService` | صفوف المقارنة الجاهزة |
| `calculate_installment` | `slug`, `down_payment`, `months`, `bank_id?`, `salary?`, `obligations?` | `CalculatorService` + `InstallmentCalculator` | القسط والإجمالي والبنك والأهلية التقديرية (نسبة الاستقطاع) |
| `list_offers` | `limit` | `OfferApiService` | العروض النشطة وتاريخ الانتهاء |
| `list_banks` | — | `CalculatorBank` | البنوك المتاحة وأقل نسبة |
| `get_showroom_info` | `topic: hours\|branches\|contact\|documents\|financing_terms\|warranty\|faq` | إعدادات الموديول + `Faq` + `about_branches` + footer | نص أو بيانات منظّمة |
| `create_lead` | `name`, `phone`, `car_slug?`, `preferred_contact_time?`, `consent=true` | `Lead` / `Booking` (المصدر: `ai_assistant`) | رقم الطلب |
| `handoff_to_human` | `reason` | إعدادات الواتساب | رابط واتساب فيه الملخص |

- **كل الأدوات للقراءة بس**، ما عدا `create_lead`. ودي بتشتغل بعد **موافقة صريحة** من العميل، وبنفس الـ validation بتاع فورمز المتجر، وبحد أقصى لكل جلسة.
- **كل أداة ليها مفتاح تفعيل في الإعدادات.** مثلاً ممكن تقفل حساب الأقساط في معرض كاش بس.
- **نتائج الأدوات بتتسجّل** في `ai_messages.tool_calls`، للمراجعة ولـ OutputGuard.

## 3. التحكم من الإعدادات (المسموح والممنوع)

### 3.1 الأقسام
| القسم | الإعدادات |
|---|---|
| **عام** | تفعيل المساعد، الظهور في المتجر، الصفحات اللي يظهر فيها، المزوّد (Gemini / Claude / OpenAI)، الموديل، API Key لكل مزوّد (مشفّر)، **زر "اختبار الاتصال"** |
| **الشخصية** | الاسم (مثلاً "نوّاف")، الصورة (الماسكوت)، رسالة الترحيب، نص الفقاعة، النبرة (رسمي / ودود / سعودي عامّي)، اللغة (تلقائي / عربي / إنجليزي)، طول الرد |
| **المواضيع المسموحة** (checkboxes) | السيارات والمواصفات · المقارنة · الأقساط والتمويل · العروض · مواعيد وفروع المعرض · المستندات المطلوبة · الحجز وتجربة القيادة · الصيانة والضمان · الاستيراد والطلب المخصص |
| **الممنوعات** (checkboxes + نص حر) | السياسة والدين · المنافسين بالاسم · وعود بالموافقة البنكية أو نسب نهائية · نصائح قانونية أو شرعية · أسعار مش موجودة في النظام · خصومات مش في العروض · بيانات عملاء تانيين · أي موضوع خارج السيارات |
| **قواعد مخصصة** | نص حر بيتضاف للتعليمات. مثلاً: "لا تذكر سيارات غير متوفرة"، "اذكر دائماً أن القسط تقديري"، "رشّح سيارات العروض أولاً" |
| **ردود جاهزة** | رد "خارج النطاق"، ورد "مش متأكد، أحولك لموظف"، والـ disclaimer بتاع التمويل |
| **معلومات المعرض** | مواعيد العمل لكل يوم (ومنها رمضان والإجازات)، الفروع (من `about_branches`)، المستندات المطلوبة، شروط التمويل، الضمان، الأسئلة الشائعة (من `Faq`) + سؤال وجواب مخصص |
| **الأدوات** | تشغيل وإيقاف كل أداة، الحد الأقصى لعدد السيارات في النتيجة، إظهار الأسعار (أيوه / لا / "تواصل معنا") |
| **جمع العملاء** | امتى يعرض فورم التواصل (بعد ترشيح / بعد N رسائل / لما العميل يطلب)، الحقول المطلوبة، توزيع الطلب على موظف (`BookingAssignmentService`)، إشعار للمسؤول |
| **الحدود والتكلفة** | رسائل لكل جلسة، رسائل لكل IP في الساعة، طول الرسالة، أقصى عدد جولات أدوات، **ميزانية يومية** (عدد الطلبات أو التوكنز)، وبعدها المساعد يقفل ويظهر واتساب |
| **الخصوصية** | مدة الاحتفاظ بالمحادثات، إخفاء أرقام الجوال من السجل بعد الحفظ، نص الموافقة |

### 3.2 تطبيق القواعد (طبقات)
1. **System prompt بيتبني من الإعدادات:** الهوية، المواضيع المسموحة والممنوعة، القواعد، ومعلومات المعرض الثابتة. وثابت عشان الـ caching.
2. **الحقائق من الأدوات بس:** تعليمات صريحة إن أي سعر أو قسط أو مواصفة أو توفر لازم يكون من نتيجة أداة في نفس المحادثة.
3. **OutputGuard بعد الرد:** أي رقم سعر أو رابط سيارة أو slug في الرد لازم يكون موجود في نتائج الأدوات. لو مش موجود، بيتشال أو بيتبدّل بكارت من النتيجة نفسها، والحالة بتتسجّل.
4. **فلتر الموضوع (اختياري):** لو الرسالة واضح إنها خارج النطاق (كلمات ممنوعة من الإعدادات)، الرد الجاهز بيرجع **من غير ما ننادي النموذج**. ده بيوفّر تكلفة.
5. **الحماية من prompt injection:**
   - كلام العميل ونتائج الأدوات مش تعليمات.
   - الأدوات مش بتنفّذ أي حاجة خطيرة.
   - `create_lead` بس، ومحتاج موافقة وvalidation.
6. **الحدود:** rate limit (`RateLimiter`)، ومدة الجلسة، والميزانية اليومية.

## 4. لوحة التحكم (الموديول في الأدمن)

لما الموديول يتفعّل من `/admin/modules`، بيظهر قسم **"المساعد الذكي"** في الـ sidebar، وفيه الصفحات دي:

| الصفحة | المحتوى |
|---|---|
| **الإعدادات** | تابات §3.1 كلها، مع حفظ واختبار اتصال |
| **التجربة (Playground)** | شات تجريبي بنفس إعدادات الإنتاج، وبيعرض استدعاءات الأدوات ونتايجها والتوكنز والتكلفة |
| **المحادثات** | قايمة (التاريخ، اللغة، عدد الرسائل، هل اتحوّلت لطلب)، وفتح المحادثة كاملة مع الأدوات، وتحويلها لطلب يدوي، وتقييم الرد (👍/👎) |
| **التقارير** | عدد المحادثات والطلبات، ونسبة التحويل، وأكتر السيارات المسؤول عنها، وأكتر الأسئلة خارج النطاق (عشان تحسّن الإعدادات)، والتكلفة اليومية |

## 6. الـ API

**المتجر** (عامة، throttle، مفيش مفاتيح):
```
GET  /api/v1/store/assistant/config        → enabled, name, avatar, greeting, bubble, quick_replies, consent_text
POST /api/v1/store/assistant/chat          → SSE: event: text | cards | tool_status | lead_form | done | error
       body: { session_id, message, context: { page, car_slug?, compare: [slugs], locale } }
POST /api/v1/store/assistant/lead          → فورم التواصل جوّه الشات (نفس validation المتجر)
POST /api/v1/store/assistant/feedback      → 👍/👎 على رسالة
```
**الأدمن** (`auth:employee` + صلاحية `manage-ai-assistant`):
```
GET/PUT  /api/v1/modules/ai-assistant/settings
POST     /api/v1/modules/ai-assistant/test-connection
POST     /api/v1/modules/ai-assistant/playground       (SSE)
GET      /api/v1/modules/ai-assistant/conversations[/{id}]
POST     /api/v1/modules/ai-assistant/conversations/{id}/convert-to-lead
GET      /api/v1/modules/ai-assistant/stats
```

## 7. الفرونت

**في الـ SDK العام (`sitekit-sdk/`)، وبيتنسخ لأي مشروع:**
- **`assistant.ts`:** client للـ SSE، و`useAssistant()` (headless). فيه الرسائل، والإرسال، والـ streaming، والكروت، والجلسة، وإعادة المحاولة. **من غير أي UI.**
- **أنواع الكروت:** `SkAssistantCard` (`cars` / `comparison` / `installment` / `showroom_info` / `lead_form` / `handoff`).

**في noauf (تصميم المشروع):**
- **`components/assistant/`:** فيه `AssistantPanel`، و`MessageBubble`، و`CarsCarousel` (بيستخدم `CarCard` الموجود)، و`ComparisonTable`، و`InstallmentCard`، و`LeadForm`، و`QuickReplies`.
- **`Assistant()` في `Home.tsx`:** يتنقل لـ `Layout`، والضغط عليه يفتح اللوحة.
- **`mappers.ts`:** بيحوّل كروت Sitekit لأنواع noauf (نفس فكرة الربط الحالية).

## 8. الأمان والخصوصية والتكلفة
- **المفاتيح:** مشفّرة بـ `Crypt`، ومش بتظهر في الـ API (بيظهر بس "•••• آخر 4 أرقام").
- **بيانات العميل:**
  - مفيش بيانات شخصية للنموذج غير اللي العميل كتبها.
  - الجوال مش بيتبعت للنموذج **بعد** ما يتحفظ في الـ lead (بيتبدّل بـ `[phone saved]`).
  - مدة احتفاظ قابلة للضبط، وأمر `assistant:prune` في الـ scheduler.
- **التكلفة:**
  - ملخص ملف العميل بدل التاريخ كله.
  - حد لعدد الجولات والتوكنز.
  - caching للـ system prompt.
  - ميزانية يومية مع إيقاف تلقائي.
  - عرض التكلفة التقديرية في التقارير.
- **الإساءة:** rate limit لكل IP ولكل جلسة، وحد لطول الرسالة، وCAPTCHA اختياري بعد حد معيّن.
- **الشفافية:** جملة "مساعد آلي، المعلومات تقديرية والأسعار النهائية يؤكدها الموظف" (قابلة للتعديل).

## 9. الاختبارات
- **`FakeLlmProvider`:** بيرجّع سيناريو مكتوب (نص + tool calls). وبيه بنختبر الـ runner والأدوات والـ SSE والـ OutputGuard من غير أي تكلفة ولا إنترنت.
- **اختبارات الأدوات:** على factories (البحث بالميزانية والقسط، والمقارنة، والقسط مع البنوك، والـ lead مع الموافقة والـ validation).
- **اختبارات القواعد:**
  - موضوع ممنوع ← رد جاهز من غير نداء.
  - سعر مش في النتائج ← بيتشال.
  - أداة متقفلة ← مش بتتبعت للنموذج.
- **مجموعة تقييم (eval):** 40–60 سؤال حقيقي بالعامية، فيهم أسئلة صعبة وخارج النطاق ومحاولات injection. بتتشغّل على كل مزوّد قبل التبديل، وبتقيس:
  - صحة الأسعار (لازم 100%).
  - الالتزام بالنطاق.
  - جودة الترشيح.
  - التحويل لطلب.

  **تشغيلها بيكلّف فلوس**، فبيتعمل بموافقتك.

## 11. قرارات محتاجة منك
1. **اسم المساعد وشخصيته:** "نوّاف"؟ والنبرة: سعودي عامّي، ولا فصحى بسيطة؟
2. **Gemini:** عندك API Key من Google AI Studio؟ ولا Vertex AI؟
3. **Claude:** موافق على إضافة `anthropic-ai/sdk` (composer) في المرحلة 5؟ وأي موديل يبقى الافتراضي: `claude-opus-5-5` (الأقوى)، ولا `claude-sonnet-5-5` / `claude-haiku-5-5` (أرخص للشات)؟
4. **الأسعار:** المساعد يقول السعر والقسط صراحة؟ ولا "تواصل معنا" لبعض السيارات؟
5. **جمع العميل:** امتى يطلب الاسم والجوال (بعد أول ترشيح؟ ولا لما العميل يطلب بس)؟
6. **الواتساب:** رقم التحويل لموظف، وهل التحويل مسموح في كل الأوقات ولا في ساعات العمل بس؟
7. **الاحتفاظ بالمحادثات:** كام يوم؟ (اقتراح: 90)
